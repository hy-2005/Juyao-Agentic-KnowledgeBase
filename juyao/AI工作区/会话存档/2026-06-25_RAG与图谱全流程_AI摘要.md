# 2026-06-25 RAG 与图谱全流程 — AI 摘要

> 前进言：快速回顾 juyao-agentic-rag 入库建图、问答编排、管理端/UI 分工。

## 核心结论

### 图谱构建（入库时自动完成）

```
文档 → load → split_into_chunks → Qdrant + ES +（可选）Neo4j
```

- 每个 **chunk** 独立：`TripleExtractor`（LLM + `kg_triple_extraction_system.md`）→ JSON 三元组 → `Neo4jTripleStore.upsert_triples`（MERGE 幂等）
- 图模型：`(Entity {name})-[:RELATED {relation}]->(Entity)`，边上存 `chunk_ids` / `doc_ids` / `source_names` / 证据片段等溯源
- 并行：`graph_writer.write_chunks_to_graph` 支持线程池（`ingest_graph_workers`）
- 生产入库：UI 上传 → Java `RagDocIngestService` → Kafka → Python `ingest_file`

### 问答 RAG（Routed 编排）

```
问题 → 意图路由(B) → direct | graph_only | vector_only → 流式作答(H)
```

| 分支 | 行为 |
|------|------|
| `direct` | 不检索、不查图 |
| `graph_only` | 问句抽实体种子 → Neo4j 多跳 → observation 注入 |
| `vector_only` | 混合检索(D) → 充分性(E) → 不足则图谱补强(F) |

- 混合检索：Multi-Query 改写 + HyDE → Qdrant + ES 并行 → 双层 RRF → 重排；HyDE 仅走向量
- HTTP：`POST /api/v1/chat/stream` → `routed_astream_chat_events` → SSE

### 图谱管理页（UI）

- **不负责构建**，只展示/CRUD 已入库 Neo4j 数据
- `RagGraphController` → FastAPI `graph.py`；前端 `KgGraphPanel` / `KgFullGraphShell` 力导向可视化

## 关键代码入口

| 阶段 | 模块 |
|------|------|
| 入库总管 | `ingestion/pipeline.py` → `ingest_file` |
| 建图 | `ingestion/graph_writer.py` + `knowledge_graph/extractor.py` + `store.py` |
| 意图路由 | `orchestration/intent_router.py` |
| 对话编排 | `orchestration/routed_flow.py` |
| 混合检索 | `retrieval/retriever.py` → `search_context` |
| 问句查图 | `knowledge_graph/observation.py` → `build_graph_observation_question_driven` |
