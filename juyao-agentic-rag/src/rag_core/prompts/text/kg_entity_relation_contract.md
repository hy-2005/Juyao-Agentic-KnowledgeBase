# 知识图谱实体关系抽取 · 共享合同

被入库（`kg_triple_extraction_system`）与查询（`question_graph_seed_system`）两侧共同引用的合同；保证两侧在规范化、闭集、JSON schema、抽取哲学上完全一致，避免漂移。

---

## 一、实体名规范化（强制）

抽取完成后、入库/匹配前，实体名（`head_name` / `tail_name`）必须经过以下流水线清洗。该规则与 `domain/graph/schema.py:35 normalize_entity_name` 函数逻辑对齐：

1. **全角 → 半角**：数字、字母、常用标点（含全角破折号、空格）统一转半角
   - 例：`ＺＴＥ－９０００` → `ZTE-9000`
2. **去括号修饰**：实体名末尾的括号注释整体删除（中英文括号均处理）
   - 例：`陆沉（陆氏本源继承人）` → `陆沉`
3. **去引号 / 书名号**：双引号、单引号、「」、『』、【】、《》一律删除
   - 例：`"合同编号"` → `合同编号`
4. **压缩空白**：连续空白合并为单个空格、首尾去空白
   - 例：`  熊大  熊二 ` → `熊大 熊二`

> 规则保守，只做无损清洗——不合并不同实体，只保证同一实体的写法统一。

## 二、谓词闭集（27 词）

`relation_predicate` 必须从以下候选集中选择；不得自创同义词（细节写进 `relation_full`）：

> 归口管理、任职于、隶属于、属于、包含、位于、坐落于、签署、签订、适用于、负责、管理、参与、发起、拥有、生产、销售、采购、供应、合作、关联、导致、引发、促成、发生于、持续至、指向、引用、依据、命名、属于（概念）

候选集不够时可选「**其他（具体动词）**」并确保全库该关系只用同一词（三选一兜底）。

## 六、JSON schema 字段清单（扁平）

根对象仅含 `triples`（数组）。数组每项为**单层扁平 JSON**，禁止嵌套对象或数组（除根上的 `triples`）。

字段清单：

| 字段 | 类型 | 说明 |
|---|---|---|
| `head_name` | string | 头实体标准称呼（规范化后） |
| `tail_name` | string | 尾实体标准称呼（规范化后） |
| `relation_predicate` | string | 谓词，闭集内 |
| `head_type` | string | 头实体大类 |
| `tail_type` | string | 尾实体大类 |
| `head_sense` | string | 头实体消歧短语（部门/版本等） |
| `tail_sense` | string | 尾实体消歧短语 |
| `relation_category` | string | 关系大类 |
| `relation_full` | string | 一句完整中文概括 |
| `modality` | string | 事实确定/推测/假设/待核实 |
| `time_text` | string | 时间 / 有效期概括 |
| `location_text` | string | 地理或场景概括 |
| `evidence` | string | 原文支撑关键句 |

## 七、抽取哲学（强制遵守）

1. **同一实体全库只用一种写法**：首次出现用全名；后续保持稳定，禁止同义改写。
2. **禁止添加括号修饰、引号、职务头衔后缀**：如 `张三（经理）` 必须写 `张三`。
3. **纯时间 / 纯地点单独当作实体节点时，分别进 `time_text` / `location_text`**：不要把时间、地点硬塞成实体节点。
4. **严禁编造具体门牌、金额、精确日期**：原文未给出则 `evidence` 用模糊表述照录。
5. **一条三元组只表达一个清晰断言**：同一对实体多种关系可多条；不要合并不同语义。
6. **不输出互为重复的反向边**：保留语义更精确的一条。
7. **原文未给出则 `evidence` 用模糊表述照录**：不要臆造细节。
8. **问句侧无原文 → `evidence` 始终填 `""`**。
